#+TITLE: Secrets

Back to the [[../README.org][README]]. Three mechanisms are in play, each with a different job.

| Mechanism     | Holds                                                                                | Where configured                       |
|---------------+--------------------------------------------------------------------------------------+----------------------------------------|
| agenix        | Static secrets that live in the repo, encrypted (YouTube Music client id and secret) | [[../modules/agenix/module.nix][agenix/module.nix]]                      |
| pass + GPG    | Passwords you look up at runtime (the Gmail password for the email account)          | [[../modules/accounts/module.nix][accounts/module.nix]], [[../modules/gpg.nix][gpg.nix]]           |
| GNOME keyring | Secret Service for desktop apps, unlocked at login through PAM (greetd and login)    | [[../modules/desktop/secret-services.nix][secret-services.nix]], [[../modules/desktop/commonDesktop.nix][commonDesktop.nix]] |

* agenix

- Recipients are listed in [[../modules/agenix/secrets/secrets.nix][secrets.nix]]. Today that is one SSH ed25519 public key.
- Each secret is declared in the home-manager part of [[../modules/agenix/module.nix][agenix/module.nix]] under =age.secrets=.
- By default agenix decrypts with =~/.ssh/id_ed25519=. If that key is missing, activation cannot decrypt anything.
- =secrets.nix= is skipped by the flake's auto-import on purpose: it is a recipient list for the agenix CLI, not a module.

** Adding a secret

1. Add an entry for the new file name in =secrets.nix= with the right public keys.
2. From the =secrets/= directory run =agenix -e <name>.age= to create and encrypt it.
3. Declare it in =agenix/module.nix= with =age.secrets.<name>.file = ./secrets/<name>.age=.
4. =git add= the new =.age= file, then rebuild.

** Rotating the key

Replace the public key in =secrets.nix=, then run =agenix -r= from the =secrets/= directory (it needs the /old/ private key to re-encrypt). Keep the old key until the rebuild succeeds.

* pass and GPG

- The password store is =~/.password-store= (package: =pass-wayland=). The email account reads its password with =pass show email/gmail=, so a rebuild fails if the store or the GPG key is missing.
- gpg-agent caches for 1 hour by default and 24 hours at most, and also serves as the SSH agent.
- Pinentry is =pinentry-emacs=, with =allow-loopback-pinentry= and =allow-emacs-pinentry= set. Passphrase prompts therefore appear inside Emacs, and the Emacs daemon has to be running (it starts with the graphical session).
- Commits are GPG-signed by default for both git and Jujutsu; the signing key is set in [[../modules/vcs.nix][vcs.nix]].

* Backups

What has to be backed up outside this repo to rebuild after a wipe:

- [ ] GPG secret key (=gpg --export-secret-keys --armor=)
- [ ] =~/.password-store= (or its remote)
- [ ] The agenix SSH private key

The restore procedure is in [[./installation.org][installation]].
